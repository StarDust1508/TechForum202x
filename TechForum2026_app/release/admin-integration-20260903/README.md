# Админка → приложение: проверенный исходник, не магазинный релиз

Код: `2e09dd80fcef4af9091ead819bacbac74104a65e`, ветка
`codex/techforum-mobile-admin-integration-20260903`. База — клиентский кандидат
`62b3e98`, а не устаревший клиент в отдельной серверной ветке.
Версия исходника пока 1.8.11 (36). Новые APK/AAB/IPA не созданы и не опубликованы.
Старые файлы `release/1.8.11-36-pre-sign` не содержат этих изменений.

## Что исправлено

- Главная, заставка, вход/восстановление доступа, настройки, помощь, новости,
  партнёры, общий бейдж и экспорт личного плана используют настройки админки.
  О форуме, карта и исследования используют тот же общий снимок данных.
- Один общий запрос вместо независимых запросов каждого экрана. Обновление при
  возвращении в приложение/восстановлении сети и раз в минуту, пока экран видим.
  Это best-effort обновление при доступном API, не мгновенная рассылка настроек.
- Неверный JSON, приватный admin envelope, невалидные ссылки, ошибка сети или
  недоступное хранилище не стирают последние корректные данные.
- Оба описания материалов исследований больше не игнорируют значения редактора.
  Содержание опубликованного текста определяет владелец в админке; резервный
  встроенный текст ограничен ранее проверенной общей формулировкой.
- Длинные даты/названия города переносятся, а не обрезаются. Проверка по
  `better-layout`: главный экран, настройки и исследования на 320/430 px.
- Экспорт личного плана содержит актуальные контакты/площадку и московское время
  UTC+3. Параметры организатора экранируются по
  [RFC 6868](https://www.rfc-editor.org/rfc/rfc6868.html), переносы строк не
  превращаются в дополнительные свойства календаря.
- Android release запрещён без настройки Firebase нужного проекта/package ID.
  Ошибка подключения Google Services больше не проглатывается.

## Что доказано

- TypeScript, 41 клиентский тест, сборка web-части в Android/iOS режимах — PASS.
- Живой публичный `/app-content`: плоский контракт из 28 полей принят валидатором.
- Локальная UI-проверка настоящего приложения через `tests/manual/appContentFixture.ts`:
  новые контакты появились в уже открытом «О приложении» без reload; главная,
  помощь и исследования используют изменённые ссылки/тексты; при HTTP 503 и
  повторном открытии сохранены последние корректные настройки.
- 320/430 px: проверенные экраны не выходят за ширину; длинные подписи читаемы.
  Физические Android/iPhone, 200% zoom и RTL в этой проверке не подтверждены.
- `cap sync android` и `CAP_APP_ID=ru.techpravo.conference cap sync ios` — PASS;
  Android/iOS получили разные, корректные mode-specific assets. Шрифты есть
  внутри обеих native public-папок, несмотря на предупреждение Vite о stylesheet.
- Android release dry-run остановился на отсутствии owner signing. Это проверка
  запрета, не успешная компиляция APK. iOS Archive не запускался: нет полного Xcode.
- Временные локальные QA-серверы остановлены. Production, рассылки, записи
  пользователей, старые скачиваемые файлы не менялись.

админка показывает только доступные учётные записи/токены и подтверждённые тесты.

## Граница удалённого управления

Этот патч не превращает админку в конструктор всех экранов. Логика интерфейса,
нативные разрешения, подпись, иконки и новые функции требуют обновления клиента.
Даты сессий редактируются в программе, а `dateLabel` — информационная подпись.
Часовой пояс экспорта зафиксирован для московской конференции; смена подписи
города не переводит расписание в другой часовой пояс. Число вопросов/оценка
длительности исследований пока встроены. Справочные/юридические тексты этим
патчем не заменяются удалённо целиком. Push-доставка на телефоне не доказана.

## Действия до выпуска

1. Android: получить существующий ключ через защищённое локальное хранение,
   сверить published/upload/app-signing certificates в RuStore. Не заменять ключ
   новым и не считать историческую debug-подпись достаточной. Ввести четыре
   `TECHFORUM_ANDROID_*` signing-переменные в защищённой локальной среде.
   Уже имеющийся Firebase client config проверен и помещён в ignored файл с
   правами 0600; Firebase Admin private key не копировался и не читался.
2. iPhone: установить полный Xcode, подключить owner Apple Developer Team,
   Bundle ID `ru.techpravo.conference`, Distribution/profile; выполнить Archive,
   Validate App, TestFlight и проверить устройство. Не выдавать source ZIP или
   неподписанный IPA за файл App Store. Metadata/privacy/support и соглашения
   нужно сверить в App Store Connect; эта работа не подтверждает их готовность.
3. На физическом Android проверить разрешение ОС, получение в шторке в foreground/
   background, tap и confirm. Firebase accepted само по себе не является PASS.
   На iPhone Push остаётся скрытым. После подписания проверить версии, SHA-256,
   встроенный `2e09dd8` и обновление поверх установленной версии без потери данных.

Сборки создаются только из этой клиентской ветки с зависимостями `npm ci`.
Затем Android: `npm run build:android`, `cap sync android`, release-проверки и
`assembleRelease bundleRelease`; iOS: `npm run build:ios`, `cap sync ios` с
`CAP_APP_ID=ru.techpravo.conference`, полный Xcode pipeline. Не копировать общий
`dist` между платформами: их Push-настройки различаются.
